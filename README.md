# 旧保单批单沿革核对（本机 Web 应用）

面向保存着多年**纸质保单、续期通知和批单**的投保人（尤其中老年用户），
帮助弄清“**某一天究竟适用哪一版条款**”：逐份录入材料与条款、把看不清的
日期保留为范围、在可缩放扫描图上框选依据，系统按指定日期生成条款沿革图、
列出**并列的适用候选**与**资料缺口**，并可导出 JSON 交接件。

> 本工具只整理沿革、候选与缺口，**不判断理赔结果**。
> 扫描图与核对数据**只存本机**（SQLite 与 `media/` 目录），不访问任何外部服务。

## 技术栈

- Python 3.12 / Django 5 / SQLite（在 Python 3.11 上同样可运行）
- 浏览器端：原生 HTML + CSS + JavaScript，无构建步骤、无外部 CDN
- 扫描图处理：Pillow

## 安装与启动

```bash
pip install -r requirements.txt
python manage.py migrate            # 初始化本机数据库
python manage.py seed_demo          # 可选：写入一套演示数据
python manage.py flush              # 清空（想清空演示数据时使用）
python manage.py runserver          # 默认监听 127.0.0.1:8000
```

浏览器打开 <http://127.0.0.1:8000/>。

扫描图保存在 `media/scans/`，数据库为仓库根目录的 `db.sqlite3`。
如需在局域网内访问，请自行评估隐私风险后加 `0.0.0.0:8000`。

## 录入流程

1. **材料清单 → ＋录入新材料**：填文件编号、类型（保单/续期通知/批单/其他）、
   签发与生效日期。**看不清的日期填“最早～最晚”两个端点**；一直有效则“止”留空。
   可同时上传扫描图。
2. 材料详情里 **＋录入条款版本**，再拆成带“段落号”的段落
   （第一条、3.2、责任免除第2项……）。局部替换按段落号对齐。
3. **沿革关系 → ＋录入关系**：
   - **全文替换**：新版本覆盖旧版本全部段落；
   - **局部替换**：勾选新版本中涉及的段落，**未涉及段落一律沿用旧文**；
   - **增补**：新版本作为补充条款与旧版本并行有效；
   - **撤销条款版本 / 撤销一条修改**：撤销只废止，**绝不自动恢复旧文**，
     被撤销处在候选中显示为“撤销缺口”。
4. 打开扫描图，点 **框选依据**，在图上拖出矩形即可把依据挂到
   材料 / 版本 / 段落 / 关系（坐标按 0~1 归一化保存，与分辨率无关）。

## 按日期核对

- 选择日期 → **生成沿革图与适用候选**。
- 同一旧版本若存在多条互不相容的修改链，会**并列多个候选**；
  日期看不清的，候选标注“含不确定日期（可能）”。
- 每个候选展示新版本→旧版本的链、局部替换后**保留下来的旧段落**、
  增补分支与缺口。
- **逐级回溯**：点链上的版本 → 版本/段落详情与原图框选；
  点关系箭头 → 关系依据；点“来源依据” → 直接跳回扫描图对应位置（自动放大聚焦）。
- 沿革图（SVG）用不同线型表示替换 / 增补 / 撤销 / 已撤销的修改 / 日期不确定。

## 自动核查

「核查问题」页持续检查四类问题：

| 检查 | 含义 |
|---|---|
| 悬空引用 | 关系指向不存在/已撤销的版本、段落或关系；局部替换段落不属于其新版本 |
| 时间倒置 | 日期区间 lo>hi；关系早于其依据材料签发或被修改版本的生效 |
| 循环修改 | 替换关系形成环 |
| 同条款重叠生效 | 同一条款两个版本生效区间必然重叠（有替换关系时降为提示） |

## 误录撤销与确认锁定

- 顶栏 **↩ 撤销误录**（或「留痕/撤销」页）：**后进先出**回退最近一步
  （录入↔删除、修改↔恢复原值、锁定↔解锁）。每步均有留痕。
- 关系可 **🔒 锁定确认**；锁定后不可修改/删除/被撤销，须先解锁。
- 修改关系后，**只有受影响条款（沿替换/增补连通分量）的已存结论标记过期**，
  其他日期与条款的结论保持有效；在留痕页可对过期结论一键重新生成。

## 导出 JSON 交接件

核对页 **⬇导出 JSON 交接件**，按所选日期导出 `handoff_<日期>.json`，包含：

- `sources`：全部材料（区间日期、扫描件本机路径、版本段落、关系、锁定状态）
- `clauses[].applicable_candidates`：并列适用候选（确定性、链、有效段落、
  每条依据的扫描件与框选坐标）
- `gaps`：撤销缺口与无覆盖缺口
- `issues`：悬空/倒置/循环/重叠等核查结果
- `disclaimer`：明确声明不判断理赔结果

交接件不内嵌扫描图二进制，仅记录其在本机的相对路径与框选坐标。

## 目录结构

```
policyhistory/      Django 项目（settings/urls/wsgi/asgi）
endorsements/
  models.py         材料/版本/段落/关系/框选/留痕/结论缓存
  engine.py         纯函数沿革推演引擎（区间日期、并列候选、缺口、核查）
  serializers.py    ORM → 引擎数据
  services.py       审计留痕、LIFO 撤销、锁定、结论下游过期
  views.py / urls.py JSON API
  management/commands/seed_demo.py
  tests.py          引擎核心规则单元测试（python manage.py test）
static/             前端 CSS/JS（api/viewer/modal/forms/query/history）
templates/          单页入口
media/scans/        本机扫描图（运行后生成）
```

## 运行测试

```bash
python manage.py test endorsements
```

覆盖：区间日期判定、悬空引用、时间倒置、循环修改、同条款重叠、
局部替换保留未涉及段落、撤销不恢复旧文、撤销修改标记边、
多链并列与不确定日期分叉。

## 隐私说明

- `DEBUG=True` 仅供本机使用；`ALLOWED_HOSTS` 限定 localhost/127.0.0.1。
- 没有任何外发请求；删除材料即从核对中隐藏（软删除，可撤销恢复）。
- 移交电脑或报废前，请自行删除 `db.sqlite3` 与 `media/`。
